## Required corrections

### R1 — expose the model's rows and the data-to-code mapping

Locations: 11.1, around lines 41–45; 11.2, around line 122; data comment around line 130.

- The entire model is still one display: `2x+y<=9, x+2y<=9, x<=4, x,y>=0`. Give each resource/production restriction its own row, with its meaning alongside it. A short table or aligned display works; keep the existing resource table and the numerical two-A/one-B example.
- The first paragraph of 11.2 packs `p`, the entire three-by-two matrix, `b`, `z`, the matrix inequality, the maximization sign and three API parameters into one block. Separate the data definition from the solver conventions. Make the product order (A, B) and row order (machine, labor, A-limit) explicit. A small symbol/meaning/value map followed by a displayed matrix, or an equivalent compact structured layout, is sufficient.
- Correct `# Hver rad bruker samme produktrekkefølge: maskin, arbeid, A-grense.` Those three names identify rows, not products. For example: `# Kolonner: A, B. Rader: maskintimer, arbeidstimer, A-grense.` The Python exercise 1 comment `Radene er kapasitetene` should likewise say that rows represent the constraints/resource requirements; the capacities are in `b`.

This is the most important outstanding clarity correction because later code and the duality notation rely on this mapping.

### R2 — make price names and price conditions explicit

Location: 11.3, “Fra prisforslag til et nytt optimeringsproblem”, around lines 218–234.

- State the assignment before using the variables: `u` is the price per machine hour, `v` per labor hour, and `w` per extra permitted A-batch, all in the relevant thousand-kroner units. The present phrase “timepriser u,v” leaves the order to be inferred from the subsequent formulas.
- Write the A-price condition, B-price condition and nonnegativity on separate rows rather than one long display. The condition-to-product correspondence should be visible without rereading surrounding text.
- When introducing the price vector, explicitly identify `q=(u,v,w)` in this example. “Each row has a price in q” is correct, but the direct mapping completes the transition from the worked example to the matrix form.
- Separate the general dual minimization and its constraints from the already established weak-duality inequality; currently all are joined into one display.

Do not replace the good concrete price proof with more general notation. The numerical proof and its two-product table already teach the main idea well.

### R3 — finish the structured capacity calculations and name the value function

Locations: 11.4, “Når en annen grense stopper produksjonen”, around line 276; depth passage “hvor lenge er prisformelen eksakt?”, around lines 354–358.

- The `Delta=2` paragraph combines the rejected time-line intersection, A-limit violation, alternative plan, both time checks, objective and the old bound. Use a few clearly separated steps or a compact check table, matching the successful `Delta=1/2` presentation immediately above it. Show how `(4,5/2)` comes from fixing `x=4` and using `x+2y=9`; this connects the new active constraints with the proposed plan instead of presenting the plan as a guess.
- The sensitivity interval says “Kontroller så kravene ett om gangen”, but puts all three checks into the same long paragraph. Give `x>=0`, `y>=0` and `x<=4` separate rows with their resulting bounds on `Delta`, then state the intersection.
- Explain that negative `Delta` means reduced machine capacity before using a two-sided interval. Define `P_*(Delta)` as the largest achievable contribution at machine capacity `9+Delta` before its first use, or simply retain the plain phrase “beste bidrag” and omit the new notation.
