::: {.panel-tabset}

### Implementasjon

En formel alene er ikke en ferdig algoritme. Programmet må også vite hvor det skal starte, når det skal stoppe, og hva det skal gjøre dersom iterasjonen ikke oppfører seg som forventet.

Funksjonen under gjentar fire handlinger: Den beregner et nytt iterat, kontrollerer at beregningene gir endelige tall, lagrer skrittlengde og residual, og sammenligner skrittlengden med toleransen. En liten hjelpefunksjon samler resultatene slik at vi slipper å gjenta den samme `return`-blokken. Linjen `residual = lambda value: …` lager en kort funksjon på én linje: Hvis likningen `f` er gitt som argument, måler den $|f(x)|$; ellers måler den fikspunktresidualen $|g(x)-x|$.

```{pyodide-python}
#| label: m2-5-fixed-point
#| feedback-context: ide-page4-reference-assumptions, ide-page4-np-6f11581d
import math

def fixed_point(g, x0, f=None, atol=1e-10, rtol=1e-10, maxiter=100):
    """Fikspunktiterasjon x_(n+1)=g(x_n), med diagnostikk."""
    x = float(x0)
    history = [x]
    steps = []
    residual = lambda value: abs(f(value)) if f is not None else abs(g(value)-value)
    residuals = [math.nan]

    def result(value, converged, reason, iterations):
        return {"x": value, "converged": converged, "reason": reason,
                "iterations": iterations, "history": np.array(history),
                "steps": np.array(steps), "residuals": np.array(residuals)}

    try:
        residuals[0] = residual(x)
    except (ArithmeticError, ValueError) as error:
        return result(x, False, "regnefeil: " + str(error), 0)
    if not (math.isfinite(x) and math.isfinite(residuals[0])):
        return result(x, False, "ikke-endelig verdi", 0)

    for iteration in range(1, maxiter + 1):
        try:
            x_new = g(x)
            step = abs(x_new - x)
            new_residual = residual(x_new)
        except (ArithmeticError, ValueError) as error:
            return result(x, False, "regnefeil: " + str(error), iteration - 1)

        if not all(math.isfinite(v) for v in (x_new, step, new_residual)):
            return result(x, False, "ikke-endelig verdi", iteration - 1)

        history.append(x_new)
        steps.append(step)
        residuals.append(new_residual)

        tolerance = atol + rtol*abs(x_new)
        if step <= tolerance:
            return result(x_new, True, "lite skritt", iteration)
        x = x_new

    return result(x, False, "maksimalt antall iterasjoner", maxiter)
```

Resultatet er en ordbok. `x` er siste tilnærming, mens `reason` og `iterations` forteller hvorfor og når programmet stoppet. Listene `history`, `steps` og `residuals` lar oss kontrollere utviklingen i etterkant. Ved regnefeil eller ikke-endelige tall returnerer funksjonen siste godkjente iterat; `iterations` teller fullførte steg. Et mislykket steg lagres ikke. Hvis residualen ikke kan beregnes allerede i startpunktet, markeres den med `nan`.

**Øv på dette:** [les tre kjøringer som en kontrollrapport](#uke2-ov-25).

### Diagnostikk

Stoppmeldingen «lite skritt» sier bare at verdien sluttet å endre seg. Derfor returnerer `fixed_point` både skrittlengden og residualen, og vi bør se på begge. I 2.4 så vi at de svarer på forskjellige spørsmål. `maxiter` hindrer en divergent eller syklisk metode i å kjøre for alltid, og kontrollen av `nan` og `inf` hindrer at ugyldige tall blir rapportert som en løsning. ### Kvadratrøtter

Til slutt ser vi på en regel der helningen i fikspunktet er null, som for $g_3$. Målet er å se hvor fort det da går.

For å beregne $\sqrt a$ kan vi løse $x^2-a=0$. Omskrivingen $x=a/x$ gir

$$x_{n+1}=\frac{a}{x_n}.$$

La oss prøve regelen med $a=2$ og $x_0=1$.

```{pyodide-python}
#| label: m2-5-a-over-x
#| feedback-context: ide-page4-reference-assumptions, ide-page4-iterate-959821b9
a = 2
def g_bad(x):
    return a/x

print(iterate(g_bad, 1, 10))
```

Følgen går i syklusen $1,2,1,2,\ldots$, så skrittlengden blir aldri mindre enn $1$. For å få en oppdatering som demper denne vekslingen, tar vi gjennomsnittet av $x$ og $a/x$:

$$x_{n+1}=\frac12\left(x_n+\frac{a}{x_n}\right).$$

Hvorfor gjennomsnittet? Produktet av de to tallene er alltid $x\cdot\frac ax=a$. Er $x$ for liten, er $\frac ax$ for stor, og omvendt. Den riktige roten $\sqrt a$ ligger derfor alltid mellom $x$ og $\frac ax$, og midtpunktet er et naturlig nytt anslag.

Cellen lager regelen for en vilkårlig $a$, kjører `fixed_point` med $a=2$ og skriver ut både iteratet og residualen $|x^2-2|$ i hvert steg.

```{pyodide-python}
#| label: m2-5-sqrt
#| feedback-context: ide-page4-reference-assumptions, ide-page4-fixed-point-93c1ac45
def make_sqrt_iteration(a):
    def g(x):
        return 0.5*(x + a/x)
    return g

def make_sqrt_equation(a):
    def f(x):
        return x*x - a
    return f

g_sqrt = make_sqrt_iteration(2)
f_sqrt = make_sqrt_equation(2)
result_sqrt = fixed_point(g_sqrt, 1, f=f_sqrt,
                          atol=1e-15, rtol=1e-15)

for n, x in enumerate(result_sqrt["history"]):
    print(f"n={n:2d}: x={x:.16f}, |x²-2|={abs(x*x-2):.3e}")
```

Hvorfor går det så fort? Regelen er $g(x)=\tfrac12\bigl(x+\tfrac ax\bigr)$, så $g'(x)=\tfrac12\bigl(1-\tfrac{a}{x^2}\bigr)$. I $x=\sqrt a$ er $a/x^2=1$, og dermed $g'(\sqrt a)=0$ – akkurat som for $g_3$ i 2.2. Den lineære delen av feilen forsvinner (helningsregelen fra 2.2), og vi får kvadratisk konvergens (2.3). I tabellen over faller residualen $|x_n^2-2|$ fra $6.9\cdot10^{-3}$ til $6.0\cdot10^{-6}$ og $4.5\cdot10^{-12}$: eksponenten dobles omtrent i hvert steg, og det gjør antall riktige sifre også.

::: {.reading-step title="Gå i dybden: hvorfor kvadreres residualen?"}

For regelen $x_{n+1}=\dfrac12\left(x_n+\dfrac{a}{x_n}\right)=\dfrac{x_n^2+a}{2x_n}$ kan vi regne ut neste residual eksakt:

$$
\begin{aligned}
x_{n+1}^2-a
&=\frac{(x_n^2+a)^2}{4x_n^2}-a
=\frac{x_n^4+2ax_n^2+a^2-4ax_n^2}{4x_n^2}\\[1mm]
&=\frac{x_n^4-2ax_n^2+a^2}{4x_n^2}
=\frac{(x_n^2-a)^2}{4x_n^2}.
\end{aligned}
$$

Residualen blir altså kvadrert og delt på $4x_n^2$. Med $a=2$ og $x_n\approx\sqrt2$ er $4x_n^2\approx8$:

$$
\frac{(6.9\cdot10^{-3})^2}{8}\approx6.0\cdot10^{-6},
\qquad
\frac{(6.0\cdot10^{-6})^2}{8}\approx4.5\cdot10^{-12},
$$

akkurat tallene i tabellen. Dette er kvadratisk konvergens fra 2.3, nå for residualen.

:::

Regelen er et spesialtilfelle av **Newtons metode**, som du møter i [prosjekt 2](project_week2.qmd).

Spindelvevet viser hvorfor det går så fort: Der kurven krysser diagonalen, er den vannrett, så trappen får nesten ingen trinn å gå.

```{pyodide-python}

#| feedback-context: ide-page4-reference-assumptions, ide-page4-cobweb-plot-7ff6f21b, ide-page4-make-sqrt-iteration-66efff32
```

### Oppsummering

**Svar på ukens spørsmål.** Ja – men bare hvis regelen er valgt med omhu. $g_1$ skyver oss bort fordi $|g_1'(r)|\approx1.40>1$. $g_2$ kommer fram, men sakte, fordi omtrent $72\,\%$ av feilen blir igjen i hvert steg. $g_3$ og regelen for $\sqrt2$ er raske fordi $g'(r)=0$. Små skritt og liten residual er nyttige kontroller, men gir ikke alene en garanti for liten løsningsfeil. For en slik garanti trenger vi også en feilgrense eller kunnskap om hvordan problemet forsterker residualen. Tallformatet begrenser dessuten nøyaktigheten vi kan oppnå.

#### Hovedlærdom

En numerisk algoritme er en formel sammen med en startverdi, et konvergensområde, et mål på framgang, et stoppkriterium og en måte å oppdage feil på. Python lar oss undersøke valgene; analyse forklarer observasjonene.

:::

::: {.reading-step title="Gå i dybden: ukens oppsummering i punkter"}

- En fikspunktiterasjon trenger en startverdi og en oppdateringsregel.
- Valget av oppdateringsregel bestemmer om og hvor raskt iterasjonen konvergerer.
- Feil, residual og skrittlengde måler forskjellige sider av beregningen.
- Et stoppkriterium må alltid kobles til et oppgitt mål og en toleranse.
- Historikk og stoppårsak gjør det mulig å kontrollere resultatet, også når metoden ikke konvergerer.

:::
